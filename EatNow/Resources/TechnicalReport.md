# EatNow 智慧點餐推薦系統技術報告

## 一、主題發想（研究動機）

在現代快節奏的生活中，人們經常面臨「今天吃什麼？」這個日常難題。特別是在面對眾多餐廳選擇時，決策疲勞往往讓用戶猶豫不決，浪費大量時間在選擇上。傳統的點餐應用程式雖然提供了便利的訂餐功能，但缺乏智慧化的推薦機制，無法有效解決用戶的選擇困難。

此外，現有的餐飲應用多數專注於商業化運營，忽略了個人用戶的決策輔助需求。許多用戶希望有一個簡單、直觀的工具來幫助他們快速做出飲食決策，同時能夠追蹤自己的飲食偏好和消費習慣。

基於這些觀察和需求，我們決定開發 EatNow 系統，旨在通過智慧推薦和數據分析，為用戶提供個性化的飲食決策輔助工具。

## 二、主題目的（研究目的）

### 主要目標
1. **解決選擇困難問題**：提供智慧化的隨機推薦功能，幫助用戶快速做出飲食決策
2. **個人化體驗**：建立用戶偏好模型，提供個性化推薦服務
3. **數據驅動決策**：通過統計分析幫助用戶了解自己的飲食習慣
4. **簡化點餐流程**：整合餐廳管理、點餐、歷史追蹤功能於一體

### 具體目標
- 減少用戶在選擇食物時的決策時間
- 提高用戶對飲食選擇的滿意度
- 建立完整的個人飲食數據檔案
- 提供直觀的使用者介面和流暢的操作體驗
- 實現離線數據儲存和跨設備同步能力

## 三、創新實作方法

### 第一段：創新性

#### 1. 智慧隨機推薦演算法
- **雙模式推薦系統**：實作個人模式和團體模式的智慧推薦
- **權重化隨機選擇**：基於用戶歷史偏好調整推薦權重
- **上下文感知**：考慮時間、季節等因素影響推薦結果
- **反饋學習機制**：根據用戶採納率動態調整推薦策略

#### 2. 創新的資料結構設計
- **單例模式資料管理**：使用 DataStore 統一管理所有應用資料
- **響應式資料綁定**：基於 SwiftUI 的 @Published 屬性實現即時更新
- **模組化架構**：各功能模組獨立設計，降低耦合度
- **混合式演算法應用**：結合氣泡排序和循序搜尋優化資料處理

### 第二段：實用性

#### 1. 用戶體驗優化
- **一鍵推薦功能**：單次點擊即可獲得推薦結果
- **視覺化統計分析**：直觀展示用戶飲食數據和趨勢
- **離線數據存取**：支援無網路環境下的完整功能使用
- **跨平台數據同步**：透過 CSV 匯出入實現數據遷移

#### 2. 實際應用價值
- **決策輔助工具**：有效解決日常飲食選擇困擾
- **消費追蹤系統**：幫助用戶控制飲食支出
- **習慣養成助手**：通過成就系統鼓勵健康飲食習慣
- **社群互動平台**：支援團體點餐和偏好分享

### 架構層級關係說明：

**展示層 → 業務邏輯層**
- HomeView ↔ DataStore（智慧推薦）
- ShopViews ↔ DataStore（餐廳管理）
- OrderViews ↔ OrderManager（點餐歷史）
- StatsView ↔ StatsCalculator（統計分析）
- SettingsView ↔ DataStore（設定管理）

**業務邏輯層 → 資料模型層**
- DataStore 管理 Shop & MenuItem、CustomFood、StatsSession
- OrderManager 管理 OrderHistory

**資料模型層 → 資料持久層**
- 所有模型資料透過 JSON Files 進行本地儲存
- 用戶設定透過 UserDefaults 儲存
- 資料匯出入透過 CSV 格式處理

**演算法層 → 展示層**
- Bubble Sort → OrderViews（排序功能）
- Sequential Search → OrderViews（搜尋功能）
- Random Selection → HomeView（推薦功能）

### 主要流程說明：

#### 1. 應用程式啟動流程
```
啟動 → 初始化 DataStore → 載入本地資料 → 顯示主頁面 → 功能選擇
```

#### 2. 隨機推薦流程（主頁）
```
選擇模式 → 生成推薦 → 顯示結果 → 用戶決策
└─ 採納：更新統計 → 儲存資料
└─ 重新推薦：回到生成推薦
```

#### 3. 點餐歷史流程（點餐）
```
載入歷史 → 顯示列表 → 用戶操作
├─ 排序：選擇排序類型 → 執行排序演算法 → 更新顯示
├─ 搜尋：輸入金額 → 循序搜尋演算法 → 顯示結果
└─ 刪除：執行刪除操作 → 更新列表
```

#### 4. 演算法應用時機
- **氣泡排序**：當用戶選擇按金額排序時觸發
- **循序搜尋**：當用戶輸入金額進行搜尋時觸發
- **隨機選擇**：當用戶請求推薦時觸發

#### 5. 資料流向
- **讀取**：本地檔案 → DataStore/OrderManager → UI 顯示
- **寫入**：UI 操作 → DataStore/OrderManager → 本地檔案儲存
- **同步**：所有資料變更都會即時反映到使用者介面

## 六、系統實作（作品介紹）

### 核心功能模組

#### 1. 智慧推薦系統 (HomeView)
- **功能特色**：提供食物和餐廳的智慧隨機推薦
- **技術實作**：
  - 使用 Swift 的隨機數生成器結合權重計算
  - 實作個人模式和團體模式的差異化推薦邏輯
  - 整合用戶歷史偏好數據影響推薦結果
- **用戶體驗**：一鍵獲得推薦，支援重新推薦和決策採納

#### 2. 餐廳管理系統 (ShopViews)
- **功能特色**：完整的餐廳和菜單 CRUD 操作
- **技術實作**：
  - 使用 SwiftUI 的導航系統實作多層級介面
  - 支援 CSV 批量匯入餐廳資料
  - 實作拖拽排序和批量操作
- **資料結構**：Shop -> MenuItem 的一對多關係設計

#### 3. 點餐歷史系統 (OrderViews)
- **功能特色**：完整的點餐流程和歷史管理
- **技術實作**：
  - 實作購物車模式的點餐邏輯
  - 整合氣泡排序和循序搜尋演算法
  - 支援多維度排序和精確搜尋
- **演算法應用**：詳細說明見下方演算法分析章節

#### 4. 統計分析系統 (StatsView)
- **功能特色**：多維度的數據分析和視覺化
- **技術實作**：
  - 使用 Chart 框架繪製統計圖表
  - 實作成就系統激勵用戶參與
  - 提供個人和團體模式的分別統計
- **數據洞察**：幫助用戶理解飲食偏好和消費習慣

#### 5. 設定管理系統 (SettingsView)
- **功能特色**：用戶個人化設定和資料管理
- **技術實作**：
  - 支援頭像自訂和使用者資料編輯
  - 提供資料重置和匯出功能
  - 整合特效開關和主題設定

## 七、演算法分析

### 氣泡排序演算法 (Bubble Sort) 實作分析

#### 演算法原理
氣泡排序是一種簡單的排序演算法，通過重複遍歷要排序的數列，比較相鄰元素並交換位置，使較大（或較小）的元素像氣泡一樣浮到數列的一端。

#### 程式碼實作
```swift
// MARK: - 氣泡排序演算法 (Bubble Sort)
private func bubbleSortByAmount(ascending: Bool) {
    let n = sortedOrders.count
    
    for i in 0..<n {
        var swapped = false
        
        for j in 0..<(n - i - 1) {
            let shouldSwap = ascending ? 
                sortedOrders[j].totalAmount > sortedOrders[j + 1].totalAmount :
                sortedOrders[j].totalAmount < sortedOrders[j + 1].totalAmount
            
            if shouldSwap {
                sortedOrders.swapAt(j, j + 1)
                swapped = true
            }
        }
        
        // 如果這一輪沒有交換，表示已經排序完成
        if !swapped {
            break
        }
    }
}
```

#### 演算法運作流程
1. **外層迴圈 (i = 0 to n-1)**：控制排序的輪數
2. **內層迴圈 (j = 0 to n-i-2)**：在未排序部分進行比較和交換
3. **比較邏輯**：根據 `ascending` 參數決定升序或降序排列
4. **交換操作**：使用 `swapAt()` 方法交換相鄰元素位置
5. **優化機制**：如果某一輪沒有發生交換，提前結束排序

#### 時間複雜度分析
- **最佳情況 O(n)**：數據已經排序，只需一輪遍歷
- **平均情況 O(n²)**：隨機排列的數據
- **最壞情況 O(n²)**：數據完全逆序排列
- **空間複雜度 O(1)**：原地排序，不需要額外空間

### 循序搜尋演算法 (Sequential Search) 實作分析

#### 演算法原理
循序搜尋（線性搜尋）是最基本的搜尋演算法，從數列的第一個元素開始，逐一檢查每個元素，直到找到目標值或搜尋完整個數列。

#### 程式碼實作
```swift
// MARK: - 循序搜尋演算法 (Sequential Search)
private func performSequentialSearch() {
    guard let targetAmount = Double(searchAmount) else {
        searchResults = []
        showingSearchResults = true
        return
    }
    
    searchResults = []
    
    // 循序搜尋實作
    for i in 0..<sortedOrders.count {
        if Int(sortedOrders[i].totalAmount) == Int(targetAmount) {
            searchResults.append(sortedOrders[i])
        }
    }
    
    showingSearchResults = true
}
```

#### 演算法運作流程
1. **輸入驗證**：檢查搜尋金額是否為有效數字
2. **結果初始化**：清空之前的搜尋結果陣列
3. **循序遍歷**：從索引 0 開始遍歷所有訂單記錄
4. **條件比較**：將每筆訂單的總金額與目標金額比較
5. **結果收集**：將符合條件的訂單加入結果陣列
6. **狀態更新**：設定顯示搜尋結果的標誌

#### 時間複雜度分析
- **最佳情況 O(1)**：目標元素在第一位
- **平均情況 O(n/2)**：目標元素在中間位置
- **最壞情況 O(n)**：目標元素在最後一位或不存在
- **空間複雜度 O(k)**：k 為符合條件的結果數量

#### 演算法優勢與應用場景
1. **實作簡單**：邏輯直觀，容易理解和除錯
2. **適用於小數據集**：在數據量不大時效率可接受
3. **支援多重匹配**：可以找到所有符合條件的結果
4. **無預處理需求**：不需要數據預先排序

### 演算法選擇理由

#### 為什麼選擇氣泡排序？
1. **教學目的**：演算法邏輯清晰，易於理解和演示
2. **穩定排序**：相等元素的相對位置不會改變
3. **適用場景**：訂單歷史數據量通常不大，效能影響有限
4. **程式碼簡潔**：實作簡單，維護成本低

#### 為什麼選擇循序搜尋？
1. **精確匹配**：支援找到所有符合金額條件的訂單
2. **無需排序**：可以在任何順序的數據上運作
3. **記憶體效率**：不需要建立索引或額外的資料結構
4. **實時搜尋**：隨時可以執行，不需要預處理
